# Feature: Accessories market (sprite avatar parts)

**Branch:** not created yet (work so far is uncommitted on `main`).
**Objective:** Turn the 1,200 Habbo-style sprite items in `apps/web-app/public/figure/` into a curated market where students spend quipus on avatar accessories, try them on before buying, and wear them across the campus, classroom and profile.

**Problem:** The store sells blob colours and SVG hats. Sprite items exist only as a raw dump (`scripts/figure-seed.sql`, 1,207 rows, effects mislabelled as clothing, flat prices, some items missing directions). Nothing curated, no try-on for sprites, no categories.
**Why:** Skins are the third quipu sink in the spec (§5.8). A market that is fun but not addictive keeps the earn/spend loop alive without breaking the anti-goal: nothing that looks like gambling.

## Already done (2026-10-18)
- Correct Habbo renderer: offsets, mirroring, geometry z-order, palette tint, `hiddenLayers` (`lib/figure.ts`, `components/sprite-figure.tsx`, `public/figure/figure-index.json` via `scripts/figure-index.mjs`).
- Bigger avatars: head-and-shoulders crop in small circles, full figure about 1.75 tiles tall in the campus.
- Free avatar builder (`components/avatar-builder.tsx`, catalog `lib/avatar-catalog.ts`): first step of the campus welcome, plus "Editar avatar" in the account menu. Saved through `PUT /api/me/avatar` into `profiles.avatar_config`. The server only accepts pieces from the free catalog.
- Precedence rule: a store part replaces the builder piece in the same slot (`spriteLayersOf` in `components/avatar.tsx`).

## Design

**Two sources, one figure.**
- `avatar_config.slots` = free base (builder).
- `profile_skins` (equipped, `kind = 'part'`) = purchases, one per slot, and they win over the base.
- Unequipping a purchase shows the base piece again.
- Paid items never go into `avatar_config`; the free-catalog allowlist enforces this.

**Catalog.**
- New skin kind `part`. `meta = { slot, item, rarity, colorable }`.
  - `item` uses the existing format: folder, or `folder#ch1-ls1-rs1`.
  - `slot` is the Habbo type: `ha`, `ea`, `fa`, `ca`, `cc`, `ch`, `lg`, `sh`, `hr`, `wa`.
- Curated list (about 60–80 items to start), not the dump.
- Effects (`fx*`, CamelCase folders) are excluded.

**Prices.**
- Fixed, in quipus, by rarity: común 10, especial 25, épica 60.
- No random packs, loot boxes, spins or countdown timers (anti-goal §2.3).
- Prestige items unlock through achievements (badges), not quipus. Example: the graduation cap (birrete) for "10 sesiones enseñadas".

**Store UX (`/tienda`).**
- New "Accesorios" tab with chips per category (Gorros, Lentes, Cara, Espalda, Chaquetas, Polos, Pantalones, Pelo).
- Large try-on fitting room (`Avatar bare`) that previews the hovered or selected item over the current figure, with a direction toggle (2 ↔ 4).
- States: comprar / poner / quitar. "Comprar y poner" in one tap.
- Insufficient balance: the existing message plus a shortcut to Enseñar.

**Colour.**
- Colourable parts take the avatar colour today.
- Phase 2: per-item colour from a fixed palette, stored as `profile_skins.meta.color` and passed as the layer tint.

## Scope
1. **Asset QA.** A script renders every candidate item in 8 directions and flags missing frames. Only items that pass are sold. Fix the open-skin-resources extractor (`library.extractor.ts` reads only `<param>`; my guess is that the `<asset source=… flipH=…>` attributes are lost, which drops entries such as `h_std_ey_1_3_0`) and regenerate `public/figure`.
2. **Data.** Migration `004_parts_market.sql`:
   - add `kind 'part'` to `skins_kind_check`;
   - optional `profile_skins.meta jsonb` (colour);
   - curated seed generated by a script from a reviewed list (`scripts/market-catalog.json` → SQL).
   - Retire `scripts/figure-seed*.sql`.
3. **API.**
   - `skins()` already returns owned/equipped.
   - `equipSkin` already resolves conflicts per slot for sprite parts; extend it to `kind 'part'`.
   - Mock mode must support everything (`lib/api/mock.ts`).
4. **Store UI.** Accessories tab, category chips, fitting room, rarity badge, achievement-locked items with "cómo se desbloquea".
5. **Admin.** `components/admin/content-shop.tsx` gains a sprite-part editor: folder picker over the catalog, live preview, rarity/price, active toggle.
6. **Live refresh.**
   - Campus presence carries the avatar in the LiveKit token metadata, set at token time. After a builder save or an equip, request a new campus token (or broadcast an `avatar` message on the data channel) so peers see the change without waiting 10 minutes.
   - The classroom reads `equipped` per session, so no change is needed there.

## Out of scope
- Selling between students (P2P resale or trading). It invites speculation and scams among minors; revisit only with an owner decision.
- Real money, gift cards, random rewards.
- Animated effects (`fx`).

## Constraints
- Minors: no gambling mechanics, quipus only, no prices in soles.
- Balance checks stay in Postgres (`buy_skin` with `lock_wallet` / `available_balance`).
- Next.js 16 (read `node_modules/next/dist/docs/` for unfamiliar APIs). Spanish UI copy, neutral tuteo.
- Asset licensing: the Habbo-derived art is third-party. Fine for a hackathon demo; replace or own the art before any public launch (`scripts/generate-own-figure.mjs` already sketches an original set).

## Acceptance criteria
- A student can preview any market item on their own figure, buy it with quipus, and see it on the campus and in class.
- Every sold item renders in all 8 directions without missing pieces.
- Buying with insufficient balance fails with the existing message; double-buying is idempotent.
- No sprite item can be set for free through `PUT /api/me/avatar`.
